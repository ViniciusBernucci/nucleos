# Observabilidade e handoff entre skills

O padrão para novos lotes é o [fluxo enxuto](fluxo-enxuto.md). Durante seu planejamento e despacho Go, não execute preparação/indexação/process/flow do Node legado nem acrescente gates/auditores/QA. As instruções operacionais Node abaixo só se aplicam ao modo legado explícito; regras de negócio e segurança do projeto permanecem vigentes.

Em CONTEXTO_EXECUTION=step, siga [Context Compiler Go](context-compiler.md): o runtime já registra sessão, métricas, logs e checkpoint. Não execute Node process/handoff/checkpoint nem importe os mesmos tokens novamente. As instruções Node abaixo pertencem ao modo direto/legado.

`quality-report` inclui achados novos/resolvidos, critérios comprovados, pares de SHA e série de requests. A correlação usa projeto, provedor, sessão, skill e agente; sem agente nativo explícito e coincidente, as razões de tokens por achado/critério ficam null. Não some relatórios derivados aos totais nativos. Leituras repetidas são observadas apenas nas chamadas read do Contexto e usam hashes da referência, sem guardar conteúdo.

Todas as skills registram início e fim da execução com `contexto.mjs process --project RAIZ --file EVENTO.json` quando o Contexto estiver preparado. A falta de instrumentação deve ser declarada; não invente duração, tokens ou execução. O evento usa ID estável por transição e os campos `status` (STARTED/PASS/FAIL/BLOCKED/OBSERVED), `at` ISO UTC, `session`, `parent`, `provider` (claude/codex/unknown), `skill`, `role`, `agent`, `batch`, `ticket`, `task`, `stage` e `duration_ms` quando medido. Não grave prompts, comandos completos, credenciais ou respostas no evento.

Comandos da CLI registram spans automaticamente no SQLite da worktree. Use `--skill`, `--agent`, `--provider`, `--session`, `--batch`, `--ticket`, `--parent` ou as variáveis `CONTEXTO_SKILL`, `CONTEXTO_AGENT`, `CONTEXTO_PROVIDER`, `CONTEXTO_SESSION`, `CONTEXTO_BATCH`, `CONTEXTO_TICKET`, `CONTEXTO_PARENT` para atribuição explícita. O runner do Observatório propaga metadados ao processo filho. Uma troca de skill interna deve registrar seu próprio evento; o rótulo da sessão inteira não prova qual skill consumiu cada token.

Antes de delegar ou retomar, gere `handoff --project RAIZ --task ID --role implementer|reviewer|auditor|qa|coordinator --mode initial|focal|integrated --max-bytes 10000`. Passe somente `payload`, IDs e referências. `checkpoint --source HASH` consulta um handoff persistido e informa `stale`; se revisão, snapshot ou evidência mudaram, gere novo pacote. Nunca use checkpoint como aprovação. O pacote reduz contexto por seleção determinística; não resume silenciosamente critérios, não chama outra IA e não força a compactação da conversa do cliente.

No erro, a CLI registra diagnóstico saneado em `errors.jsonl` no armazenamento `.contexto`, com sessão/etapa, classe e recuperação. Há rotação limitada a um arquivo anterior. Sem permissão, o erro original continua no stderr e a limitação do log é explícita. Logs são locais e acompanham o arquivo histórico seguro da worktree. `capture` continua sendo a fonte dos logs dos testes; o erro `stty` emitido pelo shell antes do Node não pode ser capturado retroativamente pela CLI.

No Observatório, `import-context CAMINHO_ABSOLUTO_DO_SQLITE --project-dir RAIZ_DA_WORKTREE` importa somente metadados permitidos. `process-report --by skill|role|agent|stage|provider|session|project|parent` mostra atividade, falhas e duração. Repita a importação para atualizar sem duplicar eventos. O relatório `report` continua exibindo somente tokens expostos pelo CLI nativo; processos não geram tokens fictícios nem duplicam requests. Skills sem telemetria nativa ficam com consumo desconhecido. Use instâncias instrumentadas de Claude Code ou Codex CLI, sem APIs pagas.
