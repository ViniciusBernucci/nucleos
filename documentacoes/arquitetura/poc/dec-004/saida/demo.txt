== 1. Caminho feliz
  ACEITO    token valido de A no tool-gateway
== 2. Casos negativos
  REJEITADO tenant adulterado no payload -> bad_signature
  REJEITADO token de A em contexto de B -> tenant_mismatch
  REJEITADO audiencia errada (ai-gateway no tool-gateway) -> bad_audience
  REJEITADO expirado (331 s apos emissao) -> expired
  REJEITADO versao revogada (ver 1 < min 2) -> version_revoked
  ACEITO    B continua valido apos revogar A (SEC-15)
  ACEITO    dispatcher: 1o uso do token
  REJEITADO dispatcher: replay do mesmo jti -> replay
  REJEITADO assinado por chave do atacante -> bad_signature
== 3. Rotacao sem downtime (duas chaves ativas no JWKS)
  chave ativa: cp-OH6-TZ0x
  publicada cp-WkyYcbDq; JWKS = [cp-OH6-TZ0x,cp-WkyYcbDq]
  ativada cp-WkyYcbDq; novo token kid=cp-WkyYcbDq
  ACEITO    token antigo (k1) durante a sobreposicao
  ACEITO    token novo (k2)
  k1 aposentada apos TTL+skew; JWKS = [cp-WkyYcbDq]
  REJEITADO token antigo (k1) apos aposentadoria -> unknown_kid
  ACEITO    token novo emitido apos aposentadoria
== 4. Revogacao de emergencia da chave de assinatura
  ACEITO    token vivo antes da revogacao
  chave cp-WkyYcbDq revogada; nova ativa cp-QGFcJMAV; JWKS = [cp-QGFcJMAV]
  REJEITADO mesmo token vivo apos revogacao -> unknown_kid
  ACEITO    runtime B reemite e volta a operar (sem novo enrollment)
== 5. Obsolescencia do estado de revogacao (max_staleness = 90 s, fail-closed)
  ACEITO    token revogado, 60 s sem refresh (dentro de max_staleness)
  REJEITADO token revogado, 91 s sem refresh (fora de max_staleness) -> revocation_state_stale
  REJEITADO apos refresh bem-sucedido -> version_revoked
